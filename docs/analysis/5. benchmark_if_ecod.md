# Phân tích benchmark IF / ECOD — `scripts/5. benchmark_if_ecod.ipynb`

Tài liệu giải thích tầng **proximity / density** trên 10 feature causal: walk-forward Isolation Forest (và ECOD nếu có `pyod`), so với baseline ETS bằng win rule chung.

Đọc kèm: [`causal_features_explore.md`](causal_features_explore.md), [`eval_anomaly_protocol.md`](eval_anomaly_protocol.md).

---

## 1. Bài toán notebook này giải quyết

| Mục | Chi tiết |
|---|---|
| Giả thuyết | Anomaly tháng hiện trên **vector feature** (không cần dự báo 1 bước) |
| Input | `data/features/causal/*_causal.csv` + `reports/eval/baseline_ets.json` |
| Output | `reports/eval/if_ecod_vs_ets.json` (+ bảng/plot trong notebook) |
| Phạm vi win rule đầy đủ | **Gạo** (synthetic recall IF tốn compute) |
| 4 chuỗi XK | So alerts/năm IF (và ECOD) vs ETS |

Đây là **tầng 3** trong kiến trúc: khác ETS (forecast residual) và Chronos (quantile interval).

---

## 2. Pipeline

```
causal CSV (10 cột)
  → warm-up MIN_TRAIN = 60 tháng
  → tại t: fit IF/ECOD trên rows < t (dropna)
  → score tháng t  (cao = bất thường hơn)
  → WARN/CRIT = quantile 97%/99% của score quá khứ [:t)
  → alerts/năm + (gạo) synthetic recall
  → beats_baseline vs ETS
```

---

## 3. Isolation Forest — cách score

- `sklearn.ensemble.IsolationForest`: `n_estimators=200`, `contamination="auto"`, `random_state=42`.  
- Score dùng: `score = -decision_function(x)` → **cao hơn = bất thường hơn** (cùng hướng với ECOD `decision_function`).  
- Fit chỉ trên lịch sử `< t`; cột NaN ở hàng \(t\) bị loại khỏi bộ feature lần đó (cần ≥ 3 cột hợp lệ).

### Ngưỡng alert causal

Với mỗi tháng \(t\):

- `hist = scores[:t].dropna()` (không gồm điểm \(t\))  
- WARN nếu `score_t ≥ hist.quantile(0.97)`  
- CRITICAL nếu `≥ hist.quantile(0.99)`

**Vì sao quantile quá khứ, không cố định contamination?**  
Contamination toàn cục giả định tỷ lệ anomaly ổn định; quantile causal cho phép ngưỡng thích ứng theo phân phối score đã thấy — và **không** dùng điểm tương lai để đặt ngưỡng.

---

## 4. ECOD (tuỳ chọn)

- Import `pyod.models.ecod.ECOD` nếu cài được; không có thì bỏ qua, không chặn notebook.  
- `contamination=0.05` khi fit; score = `decision_function`.  
- Notebook chủ yếu dùng ECOD để **đối chiếu alerts/năm**; synthetic recall đầy đủ tập trung Isolation Forest trên gạo.

---

## 5. Synthetic recall trên không gian feature

Shock nhân trên chuỗi gốc phải được **ánh xạ** sang vector feature:

| Target | Cột chỉnh |
|---|---|
| `so_luong` | Cộng \(\log f\) vào log-MoM/YoY lượng; đẩy `so_luong_robust_z12`; điều chỉnh `z_don_gia_minus_z_so_luong` |
| `tri_gia` | Tương tự trên cột trị giá |

Sau đó re-score hàng inject bằng IF fit trên lịch sử `< t`, so với WARN quantile lịch sử.

Đây là **proxy**, không hoàn toàn tương đương inject trên residual ETS — nhưng đủ để so độ nhạy theo cùng bộ hệ số `{×1.2…×3, ×0.7…×0.3}` và cùng key factors `{×2, ×0.5}`.

Chỉ chạy đầy đủ cho gạo vì vòng lặp fit lại IF mỗi tháng × mỗi hệ số × 2 target — chậm.

## 6. Kết quả đã chạy

### 6.1. Alerts / năm

| Chuỗi | IF | ECOD | ETS |
|---|---:|---:|---:|
| gạo | 0.33 | 0.33 | 0.15 |
| sắt thép các loại | 0.28 | 0.61 | 0.46 |
| xăng dầu các loại | 0.28 | 0.50 | 1.08 |
| dầu thô | 0.33 | 0.72 | 1.00 |

Trên xăng dầu / dầu thô, IF có alerts/năm **thấp hơn** ETS — thú vị cho mở rộng sau, nhưng win rule phase này khóa trên gạo trước.

### 6.2. Gạo — win rule (IF vs ETS)

| Metric | IF | ETS |
|---|---:|---:|
| Key recall | 0.326 | 0.457 |
| WARN+CRIT/năm | 0.33 | 0.15 |

- `better_recall = False` (IF kém hơn, không tăng ≥ 0.05)  
- `rate_ok = False` (0.33 > 2 × 0.15 = 0.30)  
- **`wins = False`** → giữ ETS baseline

Synthetic IF (gạo): recall ×2 lượng ~0.38, ×0.5 lượng ~0.41; trị giá còn thấp hơn (×2 ~0.26). Shock nhẹ (×1.2) gần như không bắt (~0.06).

## 7. Vì sao IF chưa thắng ETS trên gạo?

| Yếu tố | Giải thích |
|---|---|
| Tín hiệu khác | ETS so với **kỳ vọng có trend/mùa**; IF so với **đám mây feature quá khứ** — shock “nằm trong vùng biến động lịch sử” dễ bị bỏ |
| Inject proxy | Ánh xạ shock → feature là xấp xỉ; có thể làm khó IF hơn ETS (ETS inject trực tiếp trên chuỗi/residual) |
| Sample + chiều | ~150 điểm train × 10 feature; IF ổn nhưng không magic trên chuỗi ngắn có mùa vụ |
| Alerts gạo ETS rất thấp | 0.15/năm → trần 2× chỉ 0.30; IF 0.33 đã trượt `rate_ok` dù không ồn như Chronos |

## 8. Quyết định thiết kế

| Quyết định | Lý do |
|---|---|
| Walk-forward refit mỗi tháng | Mô phỏng vận hành; tránh fit một lần trên cả chuỗi (look-ahead) |
| MIN_TRAIN = 60 | Đủ cửa sổ năm + buffer trước khi score |
| Chỉ IF có synthetic đầy đủ trên gạo | Cân chi phí compute; ECOD đủ để so alerts |
| Copy `beats_baseline` từ protocol | Notebook tự chứa |
| Chưa LOF / PCA / deep AE | Cùng họ proximity — ưu tiên 1–2 đại diện; deep AE không hợp ~212 điểm |
